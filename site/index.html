    01 / SAVE

    Choose the version.

    Save a checkpoint. Export uses the latest saved revision, so your unsaved edits are never silently included.

    02 / REVIEW

    Know what goes out.

    On the Interactive Web Pages index, select the page, owner, repository and branch. Choose Review Export and inspect every listed file.

    03 / RELEASE

    Confirm, then visit.

    Confirm your right to publish the files publicly and choose Publish To GitHub. Check GitHub’s deployment, then test the public page.

    First-time setup: connect a GitHub destination +
    1. Create a dedicated repository with an initial commit and a writable branch. A README is enough to start.
    2. Configure GitHub Pages to deploy that branch from the repository root.
    3. Install the Midom GitHub App for that repository, with permission to read and write repository contents.
    4. In Midom’s Export To GitHub Pages panel, choose Connect GitHub and authorize your account. App installation and account authorization are both needed.

    An organization administrator may need to help. GitHub export must be enabled for your Midom installation.

    A FEW USEFUL DISTINCTIONS

    Before you go live.

    Can everything in Midom be exported to GitHub Pages?+

    The initial export supports one Interactive Web Page, supported bound Project media and supported pinned libraries, including Chart.js, Mermaid, Vega-Lite and Three.js. Known Midom-only navigation, live widgets, converted legacy runtime pages and unsupported library bindings are blocked during review. A connected page set is not included.

    Does saving a checkpoint publish my work?+

    No. A checkpoint saves a page version. Publishing in Midom and exporting to GitHub each require their own review and release action. Exporting to GitHub does not change the page’s Midom publication status or audience.

    Can an external AI agent publish for me?+

    Editor-only access lets an agent inspect, propose or edit drafts according to the permission you grant. Project page work can offer separate publishing permission when your organization allows it; some pages still require human publication. GitHub export has its own review and public-publication confirmation. Authorizing draft editing is not authorization to publish.

    What should I check before making a page public?+

    Review the source, scripts and media for confidential material and confirm publication rights. Anything delivered in the page can be public, including hidden display states. Author notes are not automatically exported. Test links, media and interactions on the deployed site. A successful repository update is not proof that GitHub has finished deploying.

    What if someone edits the exported files on GitHub?+

    Midom flags modified or deleted exported files for review. You can stop to retain the GitHub edits, or approve the proposed copies and page update. Copies under user-modified may also be public. Review again if the branch changes before publishing.
